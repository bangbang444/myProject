프로젝트의 `docs/` 폴더에 기술 문서를 작성합니다.

절차:
1. $ARGUMENTS에서 문서 주제를 파악합니다. 주제가 없으면 현재 작업 맥락(구현한 기능, 해결한 문제)을 바탕으로 판단합니다.
2. `docs/` 폴더의 기존 문서 파일명 규칙을 확인합니다.
3. 아래 구조로 문서를 작성합니다:
   - 날짜 (YYYY-MM-DD)
   - 제목
   - 문제 배경 — 왜 이 작업이 필요했는가
   - 문제 상황 — 구체적인 증상, 재현 조건, 코드/쿼리 예시
   - 해결 방법 선택 — 후보 방법 비교 및 선택 이유
   - 구현 — 핵심 코드와 설명
   - 결과 — 수치, 테스트 결과, 개선 효과
4. 파일명은 kebab-case로 `docs/` 하위에 저장합니다.
5. 문서 초안을 사용자에게 보여주고 수정할 부분이 있으면 반영합니다.
